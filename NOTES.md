# California Speed (arcade) static recompilation: status notes

Arcade version 2.1a (Atari Games, Midway Seattle board): R5000 little-endian MIPS IV, 3dfx Voodoo 1,
DCS2 sound (ADSP-2115), IDE hard disk. The game executable is `fs/CODE/vmunix` on the disk image,
a MIPS ELF with a full symbol table (static functions are missing from it).

## Layout

- `tools/recomp.py`: own MIPS IV -> C recompiler (N64Recomp does not fit: little-endian, MIPS IV,
  kernel code). Functions are found by control flow from the symbol table, plus pointer heuristics.
  Config in `recomp.toml` (`skip` = native replacements in `runtime/natives.cpp`, `hook` = C code
  inserted before an instruction).
- `generated/`: recompiler output (regenerated by `build.bat`).
- `runtime/`: native side.
  - `recomp.h` (interface with generated code), `runtime.cpp` (memory, MMIO dispatch, COP0, TLB,
    indirect calls, call tracing), `interrupts.cpp` (interrupts delivered at loop back-edges).
  - `galileo.cpp` (GT64010: timers, DMA, PCI config), `board.cpp` (I/O ASIC, CMOS, widget board,
    interrupt control), `ide.cpp` (PC87415 + ATA drive reading the CHD via libchdr).
  - `voodoo.cpp` (SST-1 registers, frame buffer RAM, LFB), `swrender.cpp` (software rasterizer
    ported from MAME's Voodoo pipeline, PNG frame dumps).
  - `input.cpp`, `sound.cpp`, `pic.cpp`: placeholders.
- `reference/mame/`: MAME sources used as hardware documentation (seattle.cpp, gt64xxx, midwayic,
  voodoo, dcs, adsp2100).
- `data/`: vmunix, boot ROM `caspd1_2.u32`, `calspeed.chd` (hard link), CMOS/disk-write files.
- `roms/`: contents of calspeed.zip.

## Build / run

`build.bat` (regenerates code, builds into `build/`), `run.sh [seconds] [lines]`.
Run: `build/CaliforniaSpeedArcade.exe data`. Debug env vars:
`ARC_DUMP_FRAMES=dir` (PNG every 60 vblanks), `ARC_WATCH=1` (stall watchdog with native stack),
`ARC_CALLTRACE=1` (guest call ring buffer, dumped to trace_dumpN.txt on errors / stalls),
`ARC_TRACE_MMIO=1` (every hardware access).

## Where it is

Playable: boots, attract mode, coin-up, track and car select, races at the original 57 frames/s,
rendered on the GPU (3x by default), with DCS2 sound and controller/keyboard input.

Workarounds in place: UnLock (I/O ASIC unlock) is a native stub; DIP switch 1 is on to skip the
force-feedback wheel calibration; the IDE bus-master BAR defaults to 0xF00; boot_entry's cache
probing results are written by main.cpp.

## Controls

Controller: left stick steer, RT/LT (or A/B) accelerator/brake, Start, Back = coin, X/Y/RB views,
LB radio, d-pad gears 1-4. Keyboard: arrows, Enter/1 start, 5 coin, Q/W/E views, R radio, A/S/D/F
gears, F2 test (operator menu), 9 service, F5 pause, F9 widescreen (on by default; the 3D view widens
at the next screen), F11 or Alt+Enter fullscreen (applied 1 s after start-up: switching right at start-up left the game
running sluggishly; both remembered in
settings.ini in the SDL per-user folder, %APPDATA%/cspeed-arcade/cspeed-arcade on Windows). Three coins per credit on the default settings.

## Environment variables

ARC_SCALE (GPU internal resolution, default 3), ARC_RENDERER=sw|both, ARC_HEADLESS, ARC_BACKGROUND
(window opens behind others without the focus, for test runs), ARC_INPUT (scripted input),
ARC_DUMP_FRAMES (with ARC_DUMP_EVERY=<vblanks>, ARC_DUMP_FROM=<vblank>), ARC_DUMP_GPU (GPU frames at
the internal resolution, same timing settings), ARC_DUMP_AUDIO, ARC_WATCH,
ARC_CALLTRACE, ARC_TRACE_MMIO[=device], ARC_SELECT_TIMER=1 (keep the selection screens' time limit, which
is otherwise held at 5 seconds left). Debugging: ARC_CALLCOUNT/ARC_CALLLOG=addr,... (guest calls),
ARC_PEEK=addr,... (RAM words as they change), ARC_RAMDUMP=<seconds>. The game's own diagnostics
(TestMessage) are always logged as `game: ...`; ARC_WATCH also reports the share of host time the sound
DSP takes.
Sound debugging: ARC_DCS_LOG=file (host->DSP words, stamped with host and audio time), ARC_DUMP_FIFO,
ARC_DSP_DUMP=<seconds> (program/data memory dumps and a 1 s PC profile), ARC_DSP_TRACE=file (registers
at each instruction of the first effect frame, in the format of a MAME debugger trace with
`tracelog`, for diffing against MAME). `tools/adspdis` disassembles a program memory dump.

## Next

- Starting in fullscreen made the game run sluggishly for the whole session (long "No VSYNC" screen,
  late input); the switch is now delayed by 1 s as a workaround. Fix it properly: find the real cause
  and remove the delay.
- Vertical black bars sometimes show up when driving up a steep hill.
- Artifacts remain around some 2D UI elements (e.g. the INSERT COIN text).
- Out of texture memory at the end of San Diego ("No More Unused Textures: ENDGAME/fin_time"): the
  track's sector streaming leaves texture memory at ~3.9 of 4 MB (freed textures are only reused by
  textures of the same size), and the finish needs 176 KB more. Whether it fits depends on load timing.
  The game places sprites at the top of texture memory outside its allocator, so the real board is
  presumably further from the limit; the difference is not found yet.
- Free play / operator settings defaults; idle the host CPU in the game's wait loops.
- Frame pacing against the host display (57 Hz game on 60+ Hz screens), widescreen, settings UI.
- The "No VSYNC interrupts detected" boot message; a translucent rectangle seen on the left of
  the race view (check against the software renderer).
